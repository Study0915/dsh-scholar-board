# D36. 领域记录的共享存储

## 背景

D35 确定独立发展学术工作台，并预告「领域记录关联会引入共享存储与导入导出问题，实施前须明确身份、引用、冲突、删除及迁移语义」。第一批要让组会反馈生成行动项、完成后关联结果材料、稿件与总览同步显示进展，同一事项在会议详情、稿件详情和总览里必须是同一条记录。

已有的结构化记录先例是 campus：它的 items 存在卡片的 `instance.state` 里，随 `boards/<id>.json` 落盘（`packages/model/src/campus`）。那份存储是每卡私有的，换一张卡或删掉卡片就找不到内容，也无法让多张卡片共享同一条事项。产品规划要求领域记录独立于卡片存在、跨看板修改一致、移除卡片不删除记录，并明确「不得让组件读写其他实例的私有 state」。每卡 state 这条路因此走不通，需要一处宿主管理的共享存储。

访问机制不必新造：D6 的数据源、D24 的能力与 D32 的订阅已经能让内置与用户组件等价地读写宿主管理的数据，`widget-board:usage`、`widget-board:data.read` 是不声明 permission 即免授权的先例。

## 决定

- 新增宿主级共享存储 `$DSH_HOME/widget-board/records.json`，形状 `{ version, records }`，由宿主独占读写。记录有稳定不透明 id、各自的修订号与系统管理的创建/修改时间；删除卡片不触碰记录。首批整份一份文件，串行队列内临时文件改名原子落盘，更新核 expectedRevision，过期回 409 与当前记录（沿用 D5、D21 的写入与冲突形状）。
- 关联只存指向方的前向 id，反向引用由宿主现算，不双写。删除来源记录不级联：引用方保留 id 并显示「来源缺失」。材料引用首批内嵌在记录里，仅 http/https（D26），随文本导出，不复制文件。
- 访问复用现有机制：能力 `widget-board:records.read` 与 `widget-board:records.write`，数据源 `widget-board:records` 声明 read 与 subscribe。两者都不声明 permission，因此免授权，与 `widget-board:usage` 同类；每次写入由宿主记下来源组件与卡片。永久删除仅界面可做，能力面不暴露。组件经 `widget.call` 与数据源访问，沙箱不变，碰不到其他实例的私有 state。
- 生命周期分活跃、归档、回收站与永久删除。回收站 30 天后自动清除；工作区记录上限 10000 条且总字节 16 MiB，任一先到即阻止新建。这三项由用户 2026-11-10 确认。
- 记录导出独立成 `.dshrecords`，现有 `.dshboard` 不自动获得记录备份能力。导入重映射全部 id 并经同一映射表重写前向引用，保留关联，不覆盖无关记录。
- 字段、容量、状态转换与交互的完整规格在 `docs/scholar-records-spec.md`，本 ADR 只记持久化方向。

## 后果

- 同一事项在多个视图里是同一份存储，跨视图一致只需一次写入；反向引用现算，总是一致。整份文件随记录数增长，每次保存重写整份——首批用条数与字节上限把它收在可接受范围。
- 共享存储与每卡 state 并存：campus 等旧卡照旧，静态种子与待办不受影响；领域记录不从自由文本自动推断。
- 免授权让内置与用户组件等价访问，约束改由 schema、上限、修订冲突与来源追查承担，而非一次人工确认。
- 记录备份与看板布局分开，导入导出各自演进；`.dshboard` 兼容性不变。

## 重审条件

- 记录条数或单份体积使整份写入成为瓶颈时，按 D21 拆成每条一份并维护关联索引，重新核定反向引用与跨文件一致性。
- 需要本地文件材料、多人协作、云同步或记录提醒时，另立规格与信任边界（D35 的重审条件）。
- 用户组件写记录的免授权决定若出现滥用，重新评估是否按 D6 引入绑组件版本的一次授权。
