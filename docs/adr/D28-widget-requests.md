# D28. 组件对外的请求由宿主代发

## 背景

组件跑在沙箱里，文档的 CSP 里 `connect-src` 是 `none`，它自己出不了网（D3）。D6 的数据源为此把地址写进 manifest，由宿主请求；D24 的能力再让插件把「读某个账号的 issue」这类事包装成一段宿主代码。后者每接一个外部服务就要在插件里写一段，`github.issues` 与 `dsh.account.balance` 已经是两个先例；插件作者不可能把每个人要用的接口都实现一遍。

## 决定

- `request` 从「一个地址」扩成一次完整的请求：`url`（可带 `{props}` 占位）、`method`、`headers`、`body`（JSON 文本，占位符按 JSON 转义替换）、`auth`、`cacheMs` 与 `format`。
- `format` 是响应正文的读法，省略时是 `json`。写 `atom` 时宿主先拒绝带 `DOCTYPE` 的文档、核对根元素是 Atom 命名空间下的 `feed`，再把 XML 解析成对象交给卡片：属性带 `@_` 前缀，`entry`、`author`、`link`、`category` 一律归一成数组，映射成界面仍由组件自己做。缓存按地址与格式各存一条，同一个地址的两种读法不会互相喂数据。
- `auth` 写 `{ credential, scheme }`：`scheme` 是 `bearer`、`basic` 或 `header`，写 `header` 时另用 `header` 给出请求头的名字。宿主在服务端把这件凭据的值取出来拼进请求头，组件代码从头到尾看不到这个值。
- `credential` 必须是这个组件在 `credentials` 里声明过的 `ref`；没有声明、没有凭据服务、这一项还没配置，都在请求前可见地报错（D11）。
- 主机仍按 `permissions.hosts` 收紧，回环与内网地址拒绝，不跟随重定向。地址、请求头与请求体都来自不可信的组件，判定只认这份清单。
- 每次请求记进这张卡的日志：方法、主机与路径、状态码与耗时，失败时带原因。日志活在宿主进程里，按卡留最近几十条，不写盘；凭据不进日志。
- 能力表保留给「宿主自己的服务」（例如当前登录账号的余额）。外部接口走 `request`，插件不再为它们写能力代码。

## 后果

- 任意接口都能用，组件作者只写 manifest 与响应的映射代码；接入新服务不需要改插件、也不需要重新安装。
- 值只到得了人批准过的主机与 manifest 声明过的请求头位置。组件仍能用这张卡的身份对那几个主机做事（发一条 issue、改一个仓库），批准主机的时候应当看见这件事。
- 组件拿不到值，因此「组件把值转给第三方」这条路径要同时满足「它知道目的地」与「值在它手里」；前者被主机清单挡住，后者被沙箱挡住。
- 日志是进程内的，宿主重启就清空；它用来说明刚才去了哪里，不做留存与审计。
- 换一种响应格式是加一个 `format` 的取值，不必新开能力，也不必为它改插件。XML 的结构校验与实体限制因此成了宿主这一侧的责任：带 `DOCTYPE` 的文档一律拒绝，根元素不在 Atom 命名空间下的也拒绝。

## 重审条件

- 再要支持一种非 JSON 的正文（例如 CSV 或 RSS）时，先决定解析结果交给卡片的是字符串还是结构化对象；都走 `format` 这一处，不再另开字段。
- 组件要读回凭据的值（例如自己按算法签名整段请求）时，先决定信任边界：能让组件看到值，就等于把它交给写组件的人，D27 的日志与快照也要跟着改。
- 目的地要由组件在运行时决定（任意主机）时，等于承认值对组件可读，需要重写本条与 D3 的对应部分。
- 需要留存请求日志、或需要按卡关闭日志时，重新决定它落在哪里、谁可以清掉。
