# D35. 独立学术工作台与通用能力回贡

- **取代**：D34

## 背景

2026-11-10 上游合并了四项贡献（PR #11–#14），用户仍决定独立发展面向通信方向硕博的工作台，并把通用体验改进作为上游贡献候选。用户确定先服务个人，采用看板内短记录与外部正文材料结合的方式，优先组会记录、行动项与小论文进度。学术版的领域选择和上游的通用定位需要分别维护。

## 决定

- 保留独立身份 `dsh-scholar-board`：根包名、`PACKAGE_NAME`、子包 scope `@dsh-scholar-board/*`、cordis 插件行 `ui-scholar-board`、样式类名、语义属性、提供方标识与 user-agent 使用独立名称。历史文档和原作者条目保留原名。
- 服务个人科研记录与展示，逐步覆盖组会、小论文、毕业论文、横向项目、研究生课程和其他事务。正文与大型材料可在外部维护，工作台管理短记录、摘要、进度、行动项及材料关联。多人协作与云同步须另行决策。
- 保持现有令牌、卡片与动效语言；可读性、编辑便利、布局稳定、键盘可用与运行流畅随每项功能共同验收。
- 通用缺陷修复、布局、编辑、无障碍与性能改进独立成提交。准备上游贡献时从上游最新基线建立贡献分支，核查变更是否已被上游吸收；只移植适用改动。领域默认布局、产品改名与独立身份留在本项目。
- GitHub 直装保持 `dsh plugin add github:Study0915/dsh-scholar-board`，安装时由 `prepare` 构建。上游 PR、Issue、合并、标签与 npm 发布依用户明确授权执行；规划和验收不扩大远端权限。
- LICENSE 保留上游版权并追加维护者版权；双语 README 声明来源、分叉点与独立维护关系。THIRD_PARTY.md 记录随产物分发的依赖及构建内联的库。原作者 `nwflower.*` 示例与市场条目保留作者及来源。
- 公开维护者身份使用 `Study0915` 与 GitHub noreply 邮箱。独立仓库此前的隐私历史处理不替代每次推送前对待发布内容与历史的核查。

## 后果

- 上游恢复贡献接收后，学术版继续独立维护；上游新功能按实际兼容性有选择地同步。
- 两个插件的存储、授权、提供方与皮肤定位继续隔离。公共改进需要额外验证其在上游身份与接口下的行为。
- 领域记录关联会引入共享存储与导入导出问题，实施前须明确身份、引用、冲突、删除及迁移语义。

## 重审条件

需要多人协作、云同步、完整长文编辑或本机程序执行时，重新评估产品与信任边界；增加 npm 分发或改变插件身份时，重新评估分发与兼容策略。
