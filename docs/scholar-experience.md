# 学术工作台体验验收要求

用于领域卡片与通用体验改进；既有令牌、自由布局与盒子契约仍按 D10、D16、D20。以下描述目标，当前版本是否满足须以具体任务证据判断。

## 视觉与信息层级

- 延续原有卡片比例、圆角、边框、阴影、字体层级、留白与克制动效，优先使用现有令牌及运行时原语。先做现状截图再调整，不整体替换配色或加入新的视觉体系。
- 卡片突出一个主题：标题、关键状态、主要内容、主要操作。同类型组件标题基线、内边距、按钮和状态位置保持一致；状态同时用文字表达。
- 长篇内容进入详情；摘要控制信息量，完整标题与重要期限可找到。缩小卡片时收起次要信息，不把正文压成极小字；窄布局保持主要操作可见。
- 短内容不强行填满空白，长内容采用单一、可识别的滚动区域；避免看板、卡片和详情同时出现多层滚动。
- 空态提示下一步操作；加载、无记录、筛选无结果、读取失败、权限未授予分别呈现。预览保持静态，演示内容与用户记录明确分开。

## 编辑与浏览

- 常用操作从对应卡片直接进入，新增记录不要求编辑 JSON。列表、摘要与详情使用相同名称和状态。
- 编辑保留输入与焦点；保存中、已保存、失败和冲突有可见反馈，失败保留草稿。关闭未保存内容时提示，完成后返回原筛选、滚动位置与关联上下文。
- 支持键盘进入操作、确认和退出；弹窗管理焦点，关闭后返回触发处。拖动入口与内容按钮互不抢占，必须提供可用的非拖动操作路径。
- 中文、英文、长标题、公式文本、混合单位、多作者和无日期均有样例。公式编辑和渲染另行验证，不从支持 Markdown 推断支持全部 LaTeX。
- 切换尺寸、主题、看板或展开详情时保留已保存内容，不通过重建 iframe 实现无关卡片刷新。

## 流畅性与测量

记录环境与基线后再判断改进。浏览器、宿主版本、窗口大小、配色、组件数量和合成数据量一起记录；冷启动与热操作分开统计。

| 场景 | 观察与测量 | 初始验收目标 |
|---|---|---|
| 输入、勾选、打开详情 | 本地视觉响应时延、保存反馈 | 输入不丢字；本地响应 p95 目标不超过 100ms，持久化单独测量 |
| 拖动、缩放、滚动 | 帧耗时、长任务、落点稳定性 | 60Hz 环境以主要交互帧约 16.7ms 为目标，记录超帧与超过 50ms 的主线程长任务 |
| 看板切换 | 操作至可交互时间、iframe 挂载次数 | 记录冷热 p50/p95；基线实测后确定预算，不提前承诺固定速度 |
| 连续新增、编辑与切换 | 请求数、监听器、对象 URL、内存趋势 | 完成后资源释放，无不断增长的监听器或未消费响应 |
| 暂停与减弱动效 | 计时器、后台请求、转场 | 离开视口按生命周期暂停，减弱动效下能完成相同操作 |

目标值是开发预算，不是当前结果。建议包含 10 张日常卡片与 30 张压力卡片，以及 0/1/50/200 条合成记录；实施先确认容量限制，超出上限用允许的最大值并注明。快速操作各重复至少 30 次记录 p50/p95，拖动单独采集连续轨迹；对比使用同一环境，报告异常样本。

## 每项视觉或交互任务的证据

1. 列触发场景、操作步骤与可观察的前后行为；每种改动至少一个长内容或边界样例。
2. 真实临时宿主下记录浅色、深色、窄布局、常规布局、宽布局及减弱动效。声明的尺寸族与 preview 进入既有 samples 和矩阵。
3. 检查键盘、焦点、状态反馈与刷新后持久化；共享记录还要验证跨视图一致性、删除卡片和记录恢复。
4. 性能改进提交同环境基线与结果、采样方法及原始记录；矩阵通过不能替代审美判断或性能测量。
5. 执行对应回归与现有完整 verify，记录命令、退出码、当前指纹和未执行项。浅深色视觉由用户核对，未核对标为 pending。

截图与测量用合成数据，放本地 `.debug/`；公开 PR 使用经隐私核查的材料。本流程不授权修改验证阈值、保护基线或公开发布。
