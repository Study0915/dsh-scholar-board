# 通信硕博个人科研工作台产品规划

决策日期：2026-11-10。依据用户选择：个人优先、混合记录、组会与小论文优先。本文定义目标和候选功能，执行顺序及状态以 [PLAN-scholar.md](PLAN-scholar.md) 为准；术语见 [scholar-domain.md](scholar-domain.md)。本次只规划，不代表新功能已经实现。

## 使用目标与边界

打开工作台能够回答：当前研究什么、这周推进什么、上次组会留下什么问题、稿件卡在哪里、接下来交付什么、对应证据在哪里。卡片呈现关键内容，详情承载完整短记录，记录和操作需要连贯。

在 `dsh-scholar-board` 独立发展。用户保留自由组合卡片的能力，已有看板和内容不因新模板自动改写。研究方向、学校、培养节点、投稿期限和项目阶段由用户配置。

工作台编辑要点、讨论、反馈、摘要与行动项，关联外部 Word、LaTeX、Markdown、PDF、代码、数据与演示材料。外部材料仍在原位置维护；引用失效须可见。实际支持的地址与文件类型须经宿主契约核实，不能从规划推断任意本地文件已经可打开。

多人实时编辑、账号角色、云同步、完整论文编辑器、自动投稿、自动科研结论和程序执行不在近期范围。AI 可辅助整理已有内容，写入须可审阅，不自动编造进展、阅读状态、实验结果或截止日期。

## 看板与组件组织

按使用场景组织，允许隐藏、添加和调整，候选看板逐阶段交付，不一次创建全部空看板。

| 看板 | 打开时首先看到 | 主要操作 |
|---|---|---|
| 科研总览 | 近期行动项、下次组会、正在推进的稿件、阻碍和期限 | 快速记录、完成事项、进入来源详情 |
| 组会 | 最近记录、下次汇报提纲、尚未关闭的问题 | 写要点、记反馈、生成并追踪行动项 |
| 小论文 | 当前稿件阶段、下一步、证据缺口与投稿节点 | 更新进展、关联实验与图表、记录修回 |
| 毕业论文 | 章节、研究成果对应关系与培养节点 | 更新章节状态、关联材料与里程碑 |
| 横向项目 | 个人负责交付、待确认问题、验收节点 | 记录沟通、跟进交付物与版本 |
| 课程与事务 | 本学期课程、作业考试、其他个人事务 | 快速新增、按期限查看、归档 |

科研总览保留有限的关键摘要，完整历史、长列表和正文进入详情。标签数量多时仍要可发现、可切换；具体导航沿用多看板能力，调整前提供设计稿核对。

## 第一批：组会、行动项与小论文

### 组会记录

- 字段：标题、会议日期、关联课题或稿件、汇报要点、讨论反馈、未决问题、材料引用。日期未知时允许留空，创建与修改时间由系统记录。
- 支持新建、编辑、按日期查看历史、归档与恢复；从上次记录创建新提纲时保留来源，不把未完成事项重复复制成多个任务。
- 从反馈创建行动项，保留会议来源；在会议详情、稿件详情和总览中显示同一项，完成状态一致。会议可同时关联多个稿件。
- 汇报提纲可整理为可复制的 Markdown，输出范围明确；引用材料仅展示链接与说明，不声称正文已打包。

### 行动项

- 标题、状态（待办、进行中、受阻、完成、取消）、可选期限与时区、来源、关联对象、阻碍说明及可选完成说明。
- 按近期、逾期、无期限和受阻筛选，完成项可查历史。无期限与未知期限不伪造倒计时。
- 一条行动项可关联会议和稿件；取消、完成与删除分别处理。删除来源记录时保留事项及可见的来源缺失提示，具体级联规则在存储设计中核定。
- 第一批沿用看板内展示和人工查看；新增提醒须独立说明触发、去重、时区、关闭页面后的能力与限制，不承诺系统通知。

### 小论文进度

- 稿件基本信息：标题、研究问题、关联课题、当前阶段、下一步、阻碍、目标期刊或会议、可选期限、正文与代码材料。
- 建议阶段：构思、实验、写作、内审、已投稿、修回、已接收、归档。阶段可退回，拒稿、撤稿和转投记录到投稿历史；阶段名称可在实施规格中扩展。
- 关联组会、行动项、研究记录与图表材料。阶段与完成条件由用户确认；未定义统计口径时使用阶段和清单，不显示虚构的完成百分比。
- 通信研究可选检查模板：问题与假设、系统模型、数据或信道条件、基线方法、指标与单位、参数、结果图表、结论边界。模板不绑定具体算法，不强制全部填写。
- 首批实现稿件清单、摘要、详情、阶段变更和来源关联；投稿轮次、修回逐条回复和图表证据目录在下一阶段扩展。

### 端到端场景

新建稿件 → 写下本周组会要点并关联稿件 → 记录“补充一个基线”的反馈 → 创建行动项 → 在总览处理 → 完成时附结果材料 → 回看稿件和会议时看到相同状态。重启后保留；删除卡片后重新添加仍能找到领域记录。

## 后续领域能力

| 领域 | 需要记录与展示 | 完成条件示例 |
|---|---|---|
| 文献与研究记录 | 阅读阶段、理解与问题、关联课题；仿真/实验目的、配置、种子、环境、指标单位、数据与图表引用 | 可以从结论找到对应记录和原始材料；缺失证据明确显示 |
| 小论文深化 | 图表清单、投稿轮次、编辑与审稿反馈、修订行动项 | 一轮修回能追溯反馈、改动与材料，保留旧轮次 |
| 毕业论文 | 章节、研究问题、已有成果、待补实验、开题/中期/预答辩/答辩节点 | 章节能关联小论文和研究材料，学校节点可自定义 |
| 横向项目 | 需求、个人负责范围、交付清单、版本、沟通结论、问题与验收 | 每项交付有状态、约定时间和材料；默认不展示金额与合同敏感内容 |
| 研究生课程 | 学期、课程、作业、考试、学习笔记和资料 | 可以从近期事项回到课程；重复课次、补交和跨学期有明确语义 |
| 其他事务 | 报销、申请、实习、会议出行等自定义类别 | 复用事项与期限，完成后可归档，保留个人可配置性 |

实验记录先手动录入与引用已有结果；仿真运行、GPU/远程任务控制等另立规格和权限设计。文献订阅只表示获取条目，阅读记录由用户维护。课程学分统计、培养规则校验、经费管理和多人项目协作需要额外产品决定。

## 记录与材料的设计要求

以下是后续实现约束，具体 schema、路由和容量在第一项实施任务中评审。

- 领域记录有稳定身份与版本；看板引用或筛选它们。跨看板修改保持一致，移除卡片不删除记录。
- 由宿主管理共享数据与写入，组件通过公开数据源、动作或能力访问，保持沙箱、授权、限额及用户组件等价能力。不得让组件读写其他实例的私有 state。
- 可选数据留空有清晰语义，支持日期与时刻的时区区别。草稿、保存成功、保存失败及修订冲突须可见，失败不能伪装保存成功。
- 归档收起已完成内容，回收站恢复误删内容；永久删除明确范围。首个存储规格确定保留期限与配额后再实施，不静默级联删除关联材料。
- 导出区分“看板布局”“记录与关联”“引用材料是否随包”；导入验证版本和内容，提供 ID 冲突与引用重映射策略。现有 `.dshboard` 不自动获得领域记录备份能力。
- 支持静态学术种子与待办继续使用；不从自由文本自动推断成业务记录。迁移提供预览、用户选择与失败恢复方案。
- 私有材料默认本地维护；演示、截图、测试与分享使用合成资料，导出前明确包含范围。

## 上游协作

学术能力留在独立项目；通用布局、编辑、响应式、可访问性、性能与测试稳定性可以进入上游候选清单。

1. 在学术仓库实现时把通用改进做成独立逻辑提交，说明触发场景和验证结果。
2. 准备投稿时核查上游最新代码、已合并内容与相关讨论，选定上游基线并建立单独贡献分支；历史提交先核查公开身份。
3. 移植通用改动，剔除学术包名、默认模板、业务存储与专用文案，按上游规范重新验证；有不同实现时说明适配。
4. 明显交互变化准备对比图和操作说明。创建 Issue/PR、推送目标遵循实际授权与本地保护，不向上游直接推送。
5. 合并后记录上游 PR 与合并提交，按差异同步，避免重复应用。独立学术版持续维护。

当前优先候选：编辑与保存反馈、长内容排版、尺寸变化时的控件可见性、键盘焦点、拖动缩放稳定性、重复渲染与资源释放，以及外部网络导致本地验收波动的问题。候选表示待诊断，不能直接声称存在缺陷或已经优化。
