## Waker 执行契约

每项任务的完整提示词由本节公共指令与表内对应规格小节组成；可直接发送“执行 PLAN-scholar 当前下一项，按 Waker 执行契约与对应规格完成”，不要求用户另写需求。

1. 读取 AGENTS、ARCHITECTURE、本页、对应规格与相关 ADR。从产品仓库最新 main 建任务分支；核查远端身份，不沿用旧 fork 的 origin 假设。
2. 报告任务号、基线、已有改动和文件范围。先补当前任务的 schema、校验、迁移、状态与错误语义；不提前实现后项。
3. 文件范围：每项规格列出的模块以及直接相关 contracts、model、runtime、host、client、widgets、testing、docs；仅修改确有依赖的文件，不扩大到全仓库重构。保护文件、接近 750 行的源码与范围外修改按 AGENTS 停止线处理。
4. 完成实现、真实回归和完整 `npm run verify`，记录退出码；UI 提供合成数据的浅深色、窄宽布局、键盘与尺寸矩阵证据，人工视觉未确认写 pending。外部服务核查单独记录，不决定离线回归结果。
5. 按本地实际 guard 的 verify → review-template → complete 流程记录；云端遵循仓库流程。纯文档执行文档与链接检查，不伪造产品 verify 或视觉验收。
6. 隐私检查通过后提交与推送产品任务分支，创建 PR；逐个确认该 PR 必需检查成功，再合并且保留分支。上游、标签、npm 发布仍须独立授权。
7. 更新本页状态与任务交接：完成/未完成、命令、退出码、证据路径、指纹、PR、合并 SHA、迁移影响和下一项；日志与截图留 `.debug/`，不公开个人材料。

## 共用验收

- A：从课题进入光通信文献、固定虚警率方案、多次运行、比较、图表、组会行动项；另覆盖语义通信数据划分、预算、种子、解码和指标口径。
- B：选定文献导入、保留实际阅读范围、关联材料，再完成一轮意见→行动→改动→证据→回复。
- C：需求变更→分工→测试→版本交付→验收→交接；标准版本保留原设计依据。
- D：近期事项不重复，课程跨学期、纯日期与时区正确，关闭页面后的提醒能力写明。
- E：取消 AI 建议无写入，重复确认不重复建任务，过期建议产生冲突；监控断线显示过期而不修改本地事实。
- 所有批次：保存/草稿失败保留输入、并发冲突、失效引用、容量、导入失败、重启恢复、旧包兼容、引用重映射、删除卡片不删除记录。性能结论附同环境基线。
